% ==================== CHAPITRE 1 : INTRODUCTION ====================
\chapter{Introduction}

\section{Présentation du projet}
Le présent document constitue le cahier des charges de l'application mobile de gestion avicole. Il a pour objectif de définir précisément les besoins du commanditaire, les fonctionnalités à développer, les contraintes techniques et les livrables attendus.

L'application vise à accompagner un éleveur avicole dans la gestion quotidienne de son activité en offrant :
\begin{itemize}
    \item Une traçabilité complète des dépenses et des gains
    \item Un suivi précis des prêts et remboursements
    \item Une gestion optimisée des poulaillers et des cycles de production
    \item Des prévisions fiables basées sur les données historiques
    \item Un suivi technique détaillé (aliment, eau, santé)
    \item Une frise chronologique visuelle pour suivre l'évolution des cycles
    \item Une synchronisation hors-ligne pour une utilisation sur le terrain
\end{itemize}

\section{Contexte et enjeux}
L'élevage avicole est une activité nécessitant une gestion rigoureuse des ressources financières et techniques. Le commanditaire, éleveur expérimenté, rencontre actuellement plusieurs difficultés :

\begin{itemize}
    \item \textbf{Manque de traçabilité} des dépenses et des gains
    \item \textbf{Impossibilité d'anticiper} les coûts des cycles
    \item \textbf{Gestion complexe} des prêts et échéances
    \item \textbf{Suivi approximatif} de la consommation d'aliment et d'eau
    \item \textbf{Absence de données historiques} pour améliorer la rentabilité
\end{itemize}

L'application devra répondre à ces problématiques en offrant une solution \textbf{simple, intuitive et accessible} depuis un téléphone mobile.

\section{Objectifs du projet}
\begin{enumerate}
    \item \textbf{Objectif principal :} Offrir un outil complet de gestion avicole permettant une traçabilité à 100\% des activités.
    \item \textbf{Objectif secondaire 1 :} Permettre l'anticipation des coûts et la planification des cycles.
    \item \textbf{Objectif secondaire 2 :} Faciliter la prise de décision grâce à des données fiables et structurées.
    \item \textbf{Objectif tertiaire :} Évoluer vers une solution professionnelle adaptable à différentes tailles d'exploitation.
\end{enumerate}

\section{Périmètre du projet}
\subsection{Inclus dans le périmètre}
\begin{itemize}
    \item Application mobile (Android et iOS) développée avec Flutter
    \item Backend Django avec base de données PostgreSQL
    \item Synchronisation hors-ligne
    \item Toutes les fonctionnalités décrites dans ce document
\end{itemize}

\subsection{Exclus du périmètre (version 1.0)}
\begin{itemize}
    \item Gestion avancée de la température et de la litière
    \item Prévisions globales hors cycles
    \item Intégration automatique avec les fournisseurs
    \item Signature électronique avancée
    \item Version web
    \item Amortissement des équipements
    \item Module multilingue
\end{itemize}

\subsection{Stratégie de synchronisation hors-ligne}

\subsubsection{Principe}
L'application fonctionne \textbf{même sans connexion internet}. Les données sont stockées localement et synchronisées automatiquement lorsque la connexion est rétablie.

\subsubsection{Processus de synchronisation}
\begin{enumerate}
    \item L'utilisateur saisit des données sur le mobile (ex: une dépense)
    \item Les données sont enregistrées dans \textbf{SQLite}
    \item La modification est ajoutée à la \textbf{file d'attente} (table \texttt{pending\_sync})
    \item Lorsque la connexion est disponible, l'appli envoie toutes les modifications au backend
    \item Le backend traite les opérations et renvoie les modifications récentes
    \item Les données locales sont mises à jour
    \item Les opérations synchronisées sont supprimées de la file d'attente
\end{enumerate}

\chapter{Fonctionnalités}

\section{Module 1 : Gestion des poulaillers}

\subsection{F1 - Créer un poulailler \haute}
Création d'un poulailler avec les informations suivantes :
\begin{itemize}
    \item Nom (ex: "Poulailler Nord", "Bâtiment A")
    \item Dimensions (longueur, largeur, hauteur optionnelle)
    \item Localisation
    \item Type de sol (optionnel)
    \item Nombre de mangeoires et d'abreuvoirs
\end{itemize}

\subsection{F2 - Lister les poulaillers \haute}
Liste des poulaillers avec :
\begin{itemize}
    \item Nom
    \item Statut (LIBRE / OCCUPÉ) calculé automatiquement
    \item Nombre actuel de poulets
    \item Densité (poulets/m²)
    \item Capacité maximale recommandée
    \item Indicateur visuel de densité (�� OK / �� Élevée / �� Critique)
\end{itemize}

\subsection{F3 - Fiche détaillée d'un poulailler \haute}
\begin{itemize}
    \item Informations générales (nom, dimensions, localisation)
    \item Surface totale
    \item Statut actuel
    \item Nombre de poulets actuel
    \item Capacité maximale recommandée
    \item Densité actuelle vs densité recommandée
    \item Historique des cycles
    \item Boutons d'action (migration, modification, suppression)
\end{itemize}

\subsection{F4 - Modifier un poulailler \moyenne}
Modification des informations (nom, dimensions, localisation). La modification des dimensions déclenche une alerte si la densité dépasse la nouvelle capacité.

\subsection{F5 - Gestion automatique du statut \haute}
Le statut passe automatiquement à :
\begin{itemize}
    \item \textbf{LIBRE} lorsque le nombre de poulets = 0
    \item \textbf{OCCUPÉ} lorsque le nombre de poulets > 0
\end{itemize}

\subsection{F6 - Calcul de la capacité et de la densité \haute}
\begin{itemize}
    \item Surface = Longueur × Largeur
    \item Capacité = Surface × Densité recommandée (selon l'âge des poules)
    \item Densité actuelle = Nombre de poulets / Surface
    \item Alerte en cas de surcharge
\end{itemize}

\subsection{F7 - Migration de poulets \haute}
Déplacement de poulets entre poulaillers avec :
\begin{itemize}
    \item Source et cible
    \item Nombre de poulets à migrer
    \item Âge des poulets (non modifiable, calculé automatiquement)
    \item Raison de la migration
    \item Alerte en cas de différence d'âge significative
\end{itemize}

\subsection{F8 - Supprimer un poulailler \basse}
Suppression uniquement si le poulailler est vide (0 poulet).

\subsection{F9 - Pré-remplissage initial \moyenne}
À la première ouverture, saisie de tous les poulaillers existants.

\subsection{F49 - Gestion des équipements \haute}
\begin{itemize}
    \item Saisie du nombre de mangeoires et abreuvoirs
    \item Calcul automatique du nombre recommandé (basé sur des données d'experts)
    \item Alerte en cas d'insuffisance
\end{itemize}

\subsection{F50 - Paramétrage des recommandations \moyenne}
Configuration des seuils de recommandation (nb de poulets par mangeoire/abreuvoir).

\section{Module 2 : Gestion des prêts}

\subsection{F10 - Enregistrer un prêt \haute}
Deux modes :
\begin{itemize}
    \item \textbf{Échéances imposées} : Saisie manuelle des échéances
    \item \textbf{Échéances proposées} : Calcul automatique basé sur durée et périodicité
\end{itemize}
Champs : prêteur, montant, date, taux (0\% acceptable), cycles affectés.

\subsection{F11 - Génération automatique d'échéancier \haute}
Pour les prêts à échéances proposées, calcul automatique du nombre d'échéances et du montant de chacune.

\subsection{F12 - Saisie manuelle des échéances \haute}
Pour les prêts à échéances imposées, saisie de chaque échéance (date, montant).

\subsection{F13 - Lister les prêts \haute}
Affichage avec :
\begin{itemize}
    \item Prêteur
    \item Montant total
    \item Montant restant dû
    \item Prochaine échéance
    \item Statut (ACTIF / EN RETARD / REMBOURSÉ)
    \item Type d'échéancier (IMPOSÉ / PROPOSÉ)
\end{itemize}

\subsection{F14 - Fiche détaillée d'un prêt \haute}
\begin{itemize}
    \item Informations générales
    \item Échéancier complet avec statut
    \item Cycles affectés
    \item Historique des remboursements
    \item Durée totale de remboursement
\end{itemize}

\subsection{F15 - Affecter un cycle à un prêt \haute}
Lier un cycle à un ou plusieurs prêts avec :
\begin{itemize}
    \item Montant fixe ou pourcentage des bénéfices à affecter
    \item Traçabilité des affectations
\end{itemize}

\subsection{F16 - Alerte de remboursement lors des ventes \haute}
Lors d'une vente sur un cycle affecté :
\begin{enumerate}
    \item Calcul automatique du montant à reverser
    \item Demande de confirmation du remboursement
    \item Si confirmé, déduction du capital restant dû
    \item Si non confirmé, rappel périodique
\end{enumerate}

\subsection{F17 - Gestion des prêts flexibles (sans échéance) \haute}
\begin{itemize}
    \item Pas d'échéancier généré
    \item Pas de date limite
    \item Remboursement via affectation des cycles
    \item Remboursement manuel possible
\end{itemize}

\subsection{F18 - Système de rappel \haute}
\begin{itemize}
    \item J-7, J-3, J-1 avant chaque échéance
    \item Alerte en cas de retard
    \item Rappel quotidien en attente de confirmation
    \item Paramétrable par l'utilisateur
\end{itemize}

\subsection{F19 - Calcul de la durée totale \haute}
Calcul automatique de la durée totale de remboursement.

\subsection{F20 - Remboursement manuel \moyenne}
Enregistrement d'un remboursement hors vente (épargne personnelle).

\subsection{F21 - Tableau de bord des financements \basse}
Synthèse globale des prêts (total emprunté, restant dû, prochaines échéances).

\subsection{F22 - Historique des prêts clôturés \basse}
Consultation des prêts remboursés.

% ==================== CHAPITRE 8 : CONTRAINTES ET EXIGENCES ====================
\chapter{Contraintes et Exigences}

\section{Contraintes fonctionnelles}
\begin{itemize}
    \item L'application doit fonctionner hors-ligne (mode dégradé)
    \item La synchronisation doit être transparente pour l'utilisateur
    \item Les données doivent être sauvegardées automatiquement
    \item Les calculs (bénéfices, densités, prévisions) doivent être précis
    \item L'interface doit être intuitive pour un utilisateur non technique
\end{itemize}

\section{Contraintes techniques}
\begin{itemize}
    \item Compatible Android 7.0+ et iOS 12+
    \item Temps de réponse < 500ms pour les opérations courantes
    \item Stockage local limité (SQLite)
    \item Synchronisation optimisée pour connexion faible
    \item Sécurisation des données (HTTPS, JWT)
\end{itemize}

\section{Exigences de performance}
\begin{itemize}
    \item L'application doit se lancer en moins de 3 secondes
    \item Les opérations locales (saisie) doivent être instantanées
    \item La synchronisation ne doit pas bloquer l'interface
    \item La consommation de batterie doit être optimisée
\end{itemize}

\section{Exigences de sécurité}
\begin{itemize}
    \item Authentification sécurisée (JWT)
    \item Chiffrement des données sensibles
    \item Sauvegarde régulière des données
    \item Pas de stockage des mots de passe en clair
\end{itemize}
